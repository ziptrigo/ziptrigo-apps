{% comment %} The account page's "Apps" form (issue #246). `app_rows` is a list of (product, switched on) in the user's order; `apps_form` (an `AppsForm`) is only passed back with errors. Each tile is a checkbox (`enabled`), the app's icon and name, and a drag handle; a hidden `order` input per tile sends the order the tiles are in, so reordering is just moving a tile. Every change submits (htmx, `change`). On success the server answers `HX-Reswap: none`, so the tiles stay and the keyboard focus is kept, plus the header's product links out of band: the menu follows with no reload. Only an error (422) is swapped in, over the form. `hx-sync` runs one request at a time and keeps only the last change queued. `static/accounts/js/apps_order.js` adds the dragging (SortableJS) and the arrow keys on a focused handle. Without JavaScript the Save button, shown only then, posts the checkboxes with a normal POST and redirect; ordering needs JavaScript. {% endcomment %}
